## 1. Nature and Purpose of Fixtures

The directories `tests/` and `rehearsal_mutations/` packaged within this workspace serve exclusively as **verifier-validation fixtures**:
1. `tests/` contains high-level test cases (`tests/test_rehearsal.py`) verifying that the Aegis ContractLock engine properly enforces behavioral contract depth, baseline invariance, candidate acceptance, boundary regression blocking, coverage readiness, gauntlet detection, and architectural decoupling.
2. `rehearsal_mutations/` contains the suite of 21 synthetic fault-injection mutants (`rehearsal_mutations/mutants.py`) and reference fixtures (`rehearsal_mutations/_ref/`) designed to evaluate verifier sensitivity and empirical regression detection capability.

These fixtures exist solely to validate the independent Aegis gate and confirm that the verifier functions as a rigorous, non-trivial arbiter.

## 2. Timing and Clean-Room Isolation

- **Post-Task Introduction:** These fixtures were introduced into the active workspace only **AFTER Tasks 1–4 were completed**.
- **No Agent Access During Modernization:** Neither `tests/` nor `rehearsal_mutations/` were available to:
  - the **Contract Archaeologist** (Task 1: Contract discovery & mining),

- **Independent Validation Artifacts:** These fixtures were not generated by the modernization agent, nor did they inform the design or implementation of `modern_app`. They represent an independent verifier-validation package introduced to evaluate the completed system under strict clean-room governance.

Prior verification passes temporarily referenced fixtures via parent directory paths (`PYTHONPATH=..`). For final self-contained submission, the fixtures are fully co-located within the workspace root, eliminating all external path dependencies while preserving the strict clean-room separation under which the modernization code was designed and verified.
